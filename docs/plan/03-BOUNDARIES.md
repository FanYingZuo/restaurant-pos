# 邊界規則（防止幻覺、跑偏與資料外洩）

> **每次對話開頭必讀。** 任何一條做不到 → 停下回報，不要換方法繞過。
> **專案從零開始：沒有任何既有程式碼。** 任何「既有程式長這樣」的說法都是幻覺，不可當根據。

## 0 文件地圖

| 檔案 | 角色 | 誰能改 |
| --- | --- | --- |
| `01-PLAN.md` | **規格說明書 v1，唯一規格來源**（含階段規格、決策、限制） | 只有使用者；AI 僅在被明確要求時 |
| `02-TODO.md` | 107 張卡：做哪個範圍、什麼順序。**不新增規格** | AI 只能打勾 |
| `03-BOUNDARIES.md` | 本檔：邊界、保密、流程、回報格式 | 只有使用者 |
| `04-LOG.md` | 對話紀錄、動到的程式碼、目前狀態、待決問題表 | AI 每張卡加一筆；待決的「決定」欄只有使用者能填 |

其他：`S1 凍結的 API 合約`＝路徑、欄位、錯誤碼的對照（不得違反規格說明書）；`docs/uml/`＝示意圖，不是規格。
**衝突時**：規格以 `01-PLAN.md` 為準；任兩份文件互相矛盾 → **停下回報，不自己挑一個**。

## 1 每次對話只讀

1. 本檔。
2. `02-TODO.md` 中**指定的那一張卡**，與所屬階段的「讀取」欄。
3. 「讀取」欄列出的 `01-PLAN.md` 段落。
4. 前置卡產出的程式碼，以及本卡要修改的檔案。

**不讀**：`docs/archive/` 與任何舊文件（舊企劃書、舊 `docs/todo/`、舊 `docs/spec/`、`docs/ARCHITECTURE.md`）。
需要讀清單外的檔案 → **先說明理由、等確認**。

## 2 出處規則

- API 路徑、錯誤碼、設定鍵、資料表與欄位名稱：必須在規格說明書或 API 合約找得到。
- 新的類別名、方法名：列在步驟 2 的「檔案清單」中，使用者確認後才算有出處。
- 找不到出處 → 寫「不確定」，記入 `04-LOG.md` 待決表，停下。**不要編。**
- 不得假裝讀過不存在的程式碼或檔案；沒有的東西就說沒有。

## 3 保密邊界（不該洩漏的資料）

### 3.1 機密資料清單（一律視為機密）

| 類別 | 具體項目 |
| --- | --- |
| PIN | PIN 明碼、PIN 雜湊、PIN 的 HMAC 密鑰、首位店長 PIN |
| 裝置 | 裝置憑證明碼、憑證雜湊、一次性配對碼 |
| 顧客 | 顧客 Session token（含 QR 網址中的 `#t=` 片段） |
| 解鎖 | 管理者解鎖憑證 `X-Unlock-Token` |
| 環境 | 資料庫帳密與連線字串、`.env` 內容、任何環境變數的**值** |

### 3.2 禁止出現的位置

機密資料**不得**出現在：

1. 日誌：`pos.log`、`print.log`、主控台輸出（唯二例外：首位店長 PIN 與首台裝置配對碼，依規格說明書「只印在主控台一次」）。
2. API 回應：含正常回應、錯誤訊息、驗證錯誤的欄位訊息、例外堆疊。
3. 測試快照、測試斷言輸出、測試報告。
4. Git commit 訊息、程式碼註解、README、Swagger 的 example 值。
5. 對話回報、`04-LOG.md`、待決問題描述。
6. 列印輸出：`print.log` 中的顧客 token 必須遮蔽為 `#t=****`。
   例外：`print_job.content` 欄位存**完整內容**（重印需要）；但「列印問題 API」**不回傳內容**。

### 3.3 寫法規則

- 日誌與訊息一律只記**識別碼**（員工編號、裝置編號、用餐紀錄編號），不記值。
- 實體與 DTO 的 `toString()` 不得包含機密欄位；DTO 不回傳機密欄位。
- 顧客 token 比對用**常數時間**；開桌回應**不含 token**。
- 不洩漏存在性差異（規格說明書已明訂，實作必須照做）：
  - 裝置憑證錯誤**不區分**「不存在」與「已撤銷」。
  - 員工停用後驗 PIN 回「PIN 錯誤」，**不洩漏「已停用」**。
  - 不存在的用餐紀錄與 token 不符，回**完全相同**的 `SESSION_TOKEN_INVALID`。
  - 取消品項等操作「狀態檢查之後才驗 PIN」，避免用錯 PIN 探測資料狀態。
- 測試固定資料只用明顯假值（如 PIN `1234`、token `test-token-xxxx`），不得寫入真實憑證。
- 規格說明書沒定義遮蔽格式的欄位，一律輸出「有／無」或識別碼，**不自創遮蔽格式**，需要時記待決。

### 3.4 AI 自身的行為

- **不在對話、回報、LOG、commit 訊息中貼出任何機密值**，即使使用者貼給我、即使只是為了除錯。需要引用時只說欄位名稱或來源位置。
- 不讀取、不要求、不複製 `.env` 或任何含密鑰的檔案內容到對話中。
- 寫完一張卡若發現前面卡片的程式有洩漏 → **記入待決並回報，不自己動手修**（跨卡修改屬禁止事項）。
- 不新增任何會把機密值寫出的日誌行或除錯輸出。
- 不把真實資料（員工姓名、PIN、憑證）當成測試資料。

## 4 必須停下的情況

- 規格沒寫、模稜兩可、或互相矛盾。
- 需要新依賴、新錯誤碼、新設定鍵、新資料表或欄位（規格說明書沒列的）。
- 需要修改已執行的遷移檔，或修改其他模組的程式。
- 已確認的測試看起來有錯；前面階段的測試失敗。
- 被 hook、權限或環境擋下。
- 卡片標了 ⚠ 待補（目前：無）。

停下時：說明原因 → 需要使用者決定的，寫進 `04-LOG.md` 的待決表（附建議選項，**不可自行採用**）→ 等回覆。

## 5 禁止

- 一次做超過一張卡；加卡片沒要求的功能；順便重構或修別的地方。
- 為了讓測試通過而修改已確認的測試。
- 刪除或跳過測試、加 `@Disabled`、放寬斷言。
- 引入 Lombok、H2、SockJS、付費服務。
- 違反第 3 節任何一條保密規則。
- 自行填寫 `04-LOG.md` 待決表的「決定」欄，或修改 `01-PLAN.md`（除非使用者明確要求）。

## 6 標準流程（每張卡）

| 步驟 | 內容 | 停下？ |
| --- | --- | --- |
| 1 讀取 | 依第 1 節讀檔 | |
| 2 列計畫 | 測試情境（名稱、前置資料、預期結果：錯誤碼、資料庫狀態）＋要新增／修改的檔案清單。**不寫程式** | ⛔ 等確認 |
| 3 寫測試 | 照確認的情境寫；之後不得修改 | |
| 4 實作 | 只動檔案清單內的檔案；清單外要動 → 停下 | |
| 5 跑測試 | 本卡＋同模組＋前面所有階段全部通過 | |
| 6 回報 | 依第 7 節格式；`02-TODO.md` 打勾；`04-LOG.md` 加一筆 | ⛔ 等「好」 |

- **文件卡**（S1 全部、10.3）：步驟 2 改為「列出文件大綱」；步驟 3、5 省略。
- **前端卡**（S12～S16）：步驟 2 列出「Vitest 測試情境（有純邏輯時）＋畫面驗收清單」。
- **驗收卡**（每階段最後一張）：通過且使用者回「好」，才進下一階段。

## 7 回報格式

```
## 卡 X.Y 回報
1. 修改的檔案：（與步驟 2 清單比對，標出多出或少掉的）
2. 測試結果：本卡 N／N、同模組 N／N、前面階段 N／N
3. 規格沒寫但我做了決定的地方：（沒有就寫「無」）
4. 新增的待決問題：#N（沒有就寫「無」）
5. 保密檢查：本卡是否動到機密資料的處理或輸出；有的話逐條對照第 3 節（沒有就寫「無」）
6. LOG 草稿：（依 04-LOG.md 格式）
```

## 8 使用者的止損指令

```
停。只根據卡 X.Y 和它的讀取欄回答；規格沒寫的部分記到 04-LOG.md 待決表。
```
收到後：立刻停止目前動作，列出已改動的檔案，等指示。

## 9 開工提示詞

**開始一張卡**
```
讀 docs/plan/03-BOUNDARIES.md。
再讀 docs/plan/02-TODO.md 的「卡 X.Y」與所屬階段的「讀取」欄，
以及讀取欄列出的 docs/plan/01-PLAN.md 段落。其他檔案不要讀。
只做卡 X.Y，做到步驟 2（列計畫）後停下等我確認。
```

**確認計畫後**
```
計畫確認（或：第 3 項改成……）。繼續步驟 3～6，完成後停下回報。
```

**CLAUDE.md 建議**（每次自動載入，只放指路內容，不重複寫規格）
```

- 不讀 docs/archive/ 與任何舊文件。
- 不在回答、LOG、commit 訊息中出現 PIN、憑證、配對碼、token、密鑰的值。
```
